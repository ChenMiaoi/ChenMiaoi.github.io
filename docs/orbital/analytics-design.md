# Umami 访问观测设计

状态：真实首页已改为读取 VPS 上的 Umami 汇总，正式构建加载官方访问脚本，本地开发不采集访问。独立 HTML 文件保留为历史设计预览，其中数字不参与正式页面。部署与维护见 [analytics-deployment.md](analytics-deployment.md)。

## 视觉与位置

沿用 Orbital 的深色底、纸白标题、荧黄色信号、冷青色次级数据、细线刻度与切角面板。游戏终端感来自面板结构、编号与选中线，数据名称使用准确的普通语言。

- 入口只放在首页（WelcomePortal）底部，与“一个人的探索，也期待与你相遇”并列：显示“近 30 天访客 1,284 ↗”；点击展开“访问观测”。默认收起，预览同样默认收起。档案、文章、系列、开源及关于页面不放入口。入口位置不限制统计范围，所有正式页面的访问均参与全站汇总。
- 不建独立统计页面。桌面使用锚定页脚入口、向上展开的 360px 小浮层，不占文档布局高度。手机宽度不超过视口减去 40px；正式版须基于入口位置测量可用空间，必要时改为底部弹层，短屏时限定高度并允许内部滚动。
- 展开面板：固定近 30 天区间、独立访客、访问次数（会话）、每日访客趋势、更新时间与统计口径。没有在线人数或实时脉冲，避免把缓存数据误作实时。
- 不展示文章阅读次数，不做每篇文章的统计入口或公开统计。
- 手机：面板按容器收窄，统计保持两列、其他信息换行；不需要横向滚动。
- 正式版使用站点既有字体与四语言翻译系统；预览为中文，采用本地系统字体。
- 动效：展开可用轻微透明度过渡，不做数字滚动或循环闪烁；遵循系统减少动态效果偏好。图表提供可访问文字说明及每日数据表。

## 指标和状态

全站独立访客按近 30 天区间直接查询，不累加每日 UV 或页面 UV。访问次数取 Umami 的 visits（访问会话），不使用 pageviews（页面浏览量）冒充进站次数；具体会话划分规则以实际部署版本为准。时间区间与每日分桶使用 Asia/Shanghai，并展示截止更新时间。统计从接入时间起积累，不回填虚构历史数据。

真实零值显示 0。尚未加载时显示破折号，请求失败显示“访问数据暂时无法更新”，不伪造零值。后台导出失败保留上次成功快照；页面显示截止更新时间。预览数字只存在于独立 HTML 设计预览文件。

## 接入方案

1. VPS 使用 Podman 运行官方 Umami 3.4.0 预构建镜像，固定镜像摘要，连接独立 PostgreSQL 数据库。后台仅监听 127.0.0.1:4337，通过 SSH 转发访问，不需要额外子域名或证书。
2. 站点配置公开的 tracker URL 和 website ID，仅在正式域名启用。Umami API 凭据只留在 VPS，不进入前端、静态构建或 Git。
3. VPS 定时读取 Umami API，缓存并发布白名单字段的只读汇总 JSON：区间、更新时间、全站独立访客、全站访问会话次数、每日访客数。建议 15 分钟刷新一次；失败保留上次成功快照。接口不接受任意上游查询或返回访客记录，不提供文章统计。
4. VPS 站点使用同源汇总 URL；GitHub Pages 副本使用允许其来源的 HTTPS 汇总 URL。抓取失败不影响页面阅读。
5. 核查 `ArchiveTerminal` 的导航、文章阅读面板和浏览器前进后退。以路由成功提交为统计边界，选定一种 pageview 机制，避免自动追踪与手动追踪重复。锚点、搜索筛选、面板开合和文章内容预取不计为额外浏览。文章直接打开与面板打开各计一次。
6. 初期只采集页面访问，不启用会话回放、热图或额外行为事件。公开区域只提供汇总；来源、设备等细节在私有后台查看。
